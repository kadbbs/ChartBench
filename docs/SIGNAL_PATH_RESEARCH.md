# 信号路径研究与参数热力图

这个工作流解决一个特定问题：先保留策略原始的开仓到反向信号路径，不让
止损、止盈或重复开仓提前改变样本；分析完原始路径后，再快速重放候选规则，
寻找连续而稳定的盈利参数区域。

## 固定信号口径

内置 profile：

```text
config/backtests/btc_5m_signal_path.yaml
```

固定语义：

1. 低周期固定为 5m。
2. 只使用闭合 K 线。
3. 已闭合的 1D Hull 与 1D STC 必须同向。
4. 5m 信号在收线后确认，下一根 5m 开盘执行。
5. 日线方向不匹配的反向 5m 信号被忽略。
6. 基准持仓直到符合新日线方向的有效反向 5m 信号。
7. 基准不使用止损、止盈、保本、移动保护或时间退出。
8. 持仓内的同向有效信号只记录，不改变仓位。

STC 图表线段颜色和策略方向已经分离。策略使用当前 STC 与上一根 STC
比较得到的因果方向，不读取依赖下一根数据的显示颜色。
该 profile 同时固定 Hull、UT 和 STC 的全部信号参数；最终解析值也会写入
`manifest.json`。

## UI 工作流

启动：

```bash
./myvenv/bin/python chartbench.py chart run --backtest-ui --host 127.0.0.1
```

打开：

```text
http://127.0.0.1:8050/backtests
```

页面默认选择“信号路径与热力图”。

### 实验历史整理

每张历史任务卡提供两种不同操作：

- `从列表隐藏`：只写入当前浏览器的本地隐藏清单，任务目录和所有结果文件仍然
  保留；点击右上角“已隐藏”后可以恢复显示；
- `彻底删除文件`：显示任务文件数、占用空间和引用关系，输入“彻底删除”后才会
  删除精确的 `backtest_outputs/ui/<run_id>` 目录，且无法恢复。

排队中或运行中的任务禁止彻底删除。删除被矩阵引用的基准前会显示依赖警告；
已有矩阵汇总仍然保留，但以后不能再从被删基准重放。共享行情缓存不会随任务
目录删除。

### 第一步：生成无风控样本

1. 本次操作选择“生成无风控样本”。
2. 选择 `btc_5m_signal_path`。
3. 设置时间范围和入场前上下文，默认 288 根，即 24 小时。
4. 点击“生成基准样本”。
5. 任务完成后从结果底部下载数据。

导出文件：

```text
manifest.json                    数据身份、执行语义、切分边界
episodes.csv                     开仓到有效反向信号的交易路径
signals.csv                      入场、同向、反向有效信号账本
bars.csv.gz                      唯一 5m OHLCV、完整指标特征、已闭合日线特征
llm_research_samples.jsonl.gz    仅包含完整落在研究段的模型样本
README.txt                       文件说明
```

`llm_research_samples.jsonl.gz` 不会包含验证段或最终测试段。研究段内开仓、
但到验证段才平仓的跨边界 Episode 也不会导出，避免结果路径泄漏。

每根 5m K 线记录：

- 回测距离使用的 ATR；
- STC 数值、变化量、因果方向和极值区域；
- DKX W、D、K、D-K，以及“买/卖”原始交叉；
- MHULL、SHULL、Hull 方向和当前生效的上下轨；
- UT ATR、nLoss、输入价、跟踪止损线、距离、仓位状态和 Buy/Sell 原始触发；
- 汇总后的任一多/空 marker；
- 当时可见的最近一根已闭合 1D 的 STC、MHULL、SHULL、各自方向及是否同向。

日线对齐严格复用策略时序：5m 信号 K 线收盘、下一根 5m 开盘执行时，
日线快照中的最新一根仍视为形成中，只使用倒数第二根已闭合 1D。因而
`d1_*` 字段不会读取正在形成的日线，也不会读取未来日线。

### 第二步：分析样本

模型输入把数据分成：

```text
context_bars       入场前可见序列
holding_path_bars  入场后到反向信号的结果路径
episode            开平节点、MFE、MAE、日线趋势段和结果标签
same_side_signals  持仓内被记录但未执行的同向信号
```

每条 JSONL 都携带 `bar_columns` 和 `feature_definitions`，紧凑数组可以直接
还原成具名字段。`entry_signal`、`exit_signal` 与 `same_side_signals` 还保存
节点当时策略实际读取的 marker 文本、指标数值、颜色、ATR、日线指标快照，
以及同一根 K 线的完整研究特征，便于模型解释“为什么这个节点成为有效信号”。

模型适合提出：

- 失败路径分类；
- MAE 后恢复的时间特征；
- MFE 与持仓时长分布；
- 哪类同向信号可能适合再入场；
- 候选止损、止盈或延迟退出规则。

模型结论必须转换成确定的数值规则后再回测，不能让回测读取自由文本判断。

### 第三步：运行矩阵

1. 本次操作切换为“运行止损止盈矩阵”。
2. “复用基准样本”会自动选择最近完成的基准任务。
3. 选择 ATR、百分比或价格点数。
4. 输入止损 X 轴和止盈 Y 轴。
5. 保持“揭盲最终测试段”关闭。
6. 运行矩阵。

范围格式：

```text
0.5:3:0.25
1,1.5,2,3,4
```

百分比单位直接填写百分数，例如 `0.5` 表示距离入场价 `0.5%`。

矩阵不会重新计算每一组指标。使用已有基准任务时，只加载压缩路径并执行
参数重放；没有选择基准任务时，当前任务也只计算一次指标和信号。

同一根 5m 同时触发止损和止盈时，默认使用 `stop_first`，即止损优先。
页面会显示双触发 K 线数量，候选参数应进一步使用更低周期数据验证。

### 固定百分比移动风控

“回测百分比移动风控”是在相同开仓信号路径上增加一层独立风险规则，默认值为：

- 硬止损 `3%`：相对实际开仓成交价；多单为 `E × 0.97`，空单为
  `E × 1.03`；
- 启动门槛 `8%`：相对实际开仓成交价；多单达到 `E × 1.08`、空单达到
  `E × 0.92` 后启用移动保护；
- 移动回撤 `10%`：相对启动后的持仓最佳价格；多单保护价为最高价
  `× 0.90`，空单保护价为最低价 `× 1.10`。

这三个百分比都作用于标的价格，不按杠杆或保证金收益换算。移动保护价只能向
盈利方向变化。若没有触发硬止损或移动保护，持仓仍在下一次合格反向信号的
执行价退出。

回测按 5m OHLC 执行。开盘已经穿过上一根有效保护线时按该根开盘价成交，
不会假设仍能在旧保护价成交。同一根 K 线既产生新最佳价又回撤到新保护线时，
由于无法知道高低点先后，按保护退出处理并增加“K 线内顺序不确定”计数；
若移动保护尚未启动且同根还触及硬止损，则硬止损优先。上线前应使用更低周期
或逐笔数据复核这些交易。

固定策略结果会生成：

- `strategy.csv`：策略参数、绩效和相对无风控基准的变化；
- `strategy_trades.csv`：逐笔开平仓、退出原因、最佳价和有效保护价。

固定的 `3/8/10` 只是一组预先指定候选，不构成参数稳定区证明。若结果可接受，
仍应围绕三个参数设计训练/验证矩阵，并最后进行一次未参与选参的盲测。

## 规则前后盈亏对比

基准结果和矩阵候选使用完全相同的数据集、初始权益、仓位、手续费、滑点与
揭盲范围。矩阵结果会直接显示“无风控基准 / 加入规则后 / 变化”三列，包括：

- 最终权益、净利润、总盈利与总亏损；
- 收益率、研究段收益与验证段收益；
- 最大回撤、盈利因子与胜率；
- 盈利交易数、亏损交易数、平均每笔收益、手续费和交易数；
- 止损退出、止盈退出、反向信号退出与同向再入场交易数。

`matrix.csv` 的每一行也包含对应的 `baseline_*` 和
`*_delta_vs_baseline` 字段。因此不能只根据“加入止损后胜率提高”作判断：
需要同时检查净利润、总亏损、最大回撤、手续费和验证段相对基准的变化。

## 现代策略评估指标

页面的“现代策略体检”不使用不等间隔的单笔交易收益，而是先构造 UTC 日末
逐日盯市清算权益；没有交易的日期也保留为零收益。加密市场统一按
`365.25` 天年化，风险自由利率和最低可接受收益暂设为 `0`，实际资金成本
需要在实盘评估时另行扣除。

收益与风险效率：

- `CAGR`：年化复合增长率；
- 年化波动率与 `Sharpe`：每单位总波动获得的收益；
- `Sortino`：只用低于最低可接受收益的下行偏差；
- `Calmar`：CAGR 除以路径最大回撤；
- `Omega`：0 门槛以上收益总和除以门槛以下损失总和；
- `Ulcer Index / Martin`：同时惩罚回撤深度和持续时间。

尾部和路径风险：

- 日 `VaR 95%`：日损失的 95% 分位点；
- 日 `Expected Shortfall 95%`：最差 5% 交易日的平均损失，比 VaR 更能描述尾部；
- 最长回撤持续天数；
- 收益偏度和超额峰度，用于识别左尾与肥尾，不能默认收益服从正态分布。

统计可信度：

- `PSR > 0` 与 `PSR > 1`：Probabilistic Sharpe Ratio；结合样本长度、偏度和峰度，
  分别估计真实年化 Sharpe 超过 0 和 1 的概率；
- `95% 最短记录`：让“真实年化 Sharpe > 1”达到 95% 置信度所需的日数；
- `DSR`：Deflated Sharpe Ratio；在 PSR 上进一步校正本次无风控基准与参数矩阵的多重试验；
- `PBO`：Probability of Backtest Overfitting；用 CSCV 检查样本内获胜组合在
  样本外跌到全部组合中位数以下的频率，越低越好；
- CSCV 样本内 / 样本外 Sharpe 与性能衰减。

DSR 只知道当前矩阵实际运行的组合数，过去手工尝试但没有记录的参数不会自动
计入，因此它仍可能高估可信度。PBO 在观察值足够时把研究+验证逐日收益切成
8 个连续分块，执行 70 个对称样本内/样本外组合；最终测试未揭盲时不参与
DSR、PBO、排名或热力图。

这些指标没有脱离策略、市场和成本假设的万能通过线。实际筛选至少同时要求：
验证段为正、热力图形成连续稳定区、DSR/PSR 有统计支持、PBO 不高、尾部损失
可承受，最后再进行一次不调参的盲测。

## 热力图含义

热力图的每一格严格对应唯一一组：

```text
X = stop_loss
Y = take_profit
```

不会从其他隐藏参数中挑选最高分填入格子。其他参数，例如同向再入场次数、
冷却时间和同 K 线规则，都是本次矩阵的固定切片。

可以切换显示：

- 验证段收益；
- 验证段相对无风控基准的收益变化；
- 研究段收益；
- 总收益；
- 相对无风控基准的净利润变化；
- CAGR、Sharpe、Sortino 与 Calmar；
- PSR、DSR 与日 Expected Shortfall 95%；
- 最大回撤；
- 盈利因子；
- 3×3 邻域盈利比例。

候选详情同时显示当前可见区间的逐年收益和正收益年度比例，避免只看累计值。

稳定格要求：

```text
当前格验证收益 > 0
验证段至少 5 笔交易
当前格拥有完整 3×3 邻域（边界格不判定为稳定中心）
3×3 邻域至少 80% 盈利
邻域最差验证收益 > 0
```

相邻稳定格会被合并成连续区域。推荐候选取最大稳定区域的中心，而不是单格
最高收益。

## 数据切分与揭盲

时间顺序固定为：

```text
研究段 60%
验证段 20%
最终测试段 20%
```

研究段和验证段参与候选选择，最终测试段不参与排序。只有参数和实现已经锁定
后才勾选“揭盲最终测试段”。如果根据测试结果继续调参，测试段就已经变成新的
验证段，需要向后保留新的未见数据。

基准页中的“全样本有效信号、同向信号、闭合路径”是数据清单数量；收益、
胜负笔数及标注为“可见”的持仓/MFE/MAE 统计只使用研究段和验证段。因此在
未揭盲时，全样本闭合路径数可能大于当前可见交易数。

如果一笔持仓跨越研究/验证或验证/测试边界，区间收益使用边界最后一根可见
5m K 线的可清算价值，不会把未来反向信号的平仓价格倒灌到前一段。页面中的
“边界估值持仓”会显示这种情况；它不是策略新增的止损或真实平仓。

相关方法来源包括 Bailey 与 López de Prado 的 Probabilistic/Deflated Sharpe
Ratio、Bailey 等人的 CSCV/PBO，以及 Rockafellar 与 Uryasev 的 Conditional
Value-at-Risk（Expected Shortfall）框架。

## CLI

生成基准：

```bash
./myvenv/bin/python chartbench.py backtest baseline \
  --profile btc_5m_signal_path \
  --context-bars 288
```

直接重新计算并运行矩阵：

```bash
./myvenv/bin/python chartbench.py backtest heatmap \
  --profile btc_5m_signal_path \
  --stop-unit atr \
  --stop-values 0.5:3:0.25 \
  --take-values 0.75:6:0.25
```

复用已有 CLI 或 UI 数据集：

```bash
./myvenv/bin/python chartbench.py backtest heatmap \
  --profile btc_5m_signal_path \
  --baseline-dataset backtest_outputs/ui/RUN_ID/dataset/internal.json.gz \
  --stop-values 0.5:3:0.25 \
  --take-values 0.75:6:0.25
```

回测固定 `3% / 8% / 10%` 百分比移动风控：

```bash
./myvenv/bin/python chartbench.py backtest trailing \
  --profile btc_5m_signal_path \
  --baseline-dataset backtest_outputs/ui/RUN_ID/dataset/internal.json.gz \
  --hard-stop-pct 3 \
  --trailing-activation-pct 8 \
  --trailing-drawdown-pct 10
```

同向再入场切片：

```bash
./myvenv/bin/python chartbench.py backtest heatmap \
  --profile btc_5m_signal_path \
  --baseline-dataset PATH_TO_INTERNAL_JSON_GZ \
  --max-reentries 2 \
  --reentry-cooldown-bars 12
```

当前再入场定义为：一次止损或止盈导致空仓后，等待下一次记录到的同向有效
信号重新开仓；持仓中不会金字塔加仓。
